# Инструкции для ИИ-агентов (Jules Vision)

Добро пожаловать в репозиторий `searxng-mcp-gateway`! Этот документ содержит ключевые инструкции, архитектурные особенности и правила, которые помогут вам работать в этом проекте эффективно и безопасно.

## 1. Стек и зависимости

Проект представляет собой MCP-сервер для интеграции метапоисковой системы SearXNG.

- **Язык:** Python (>= 3.10)
- **Основной фреймворк:** MCP (Model Context Protocol), используется `FastMCP` (`mcp>=1.0.0`)
- **HTTP-клиент:** `requests` (`requests>=2.28.0`) для взаимодействия с SearXNG и внешними API.
- **Опциональные зависимости (тестирование):** `pytest>=7.0.0`, `pytest-cov>=4.0.0`
- **Дополнительно:** `memory-gateway` для семантической памяти.

## 2. Команды верификации

Перед сдачей любой работы (созданием PR) необходимо убедиться, что код работает корректно.

- **Установка для разработки (с зависимостями для тестов):**
  ```bash
  python -m pip install -e .[dev]
  ```
- **Запуск всех тестов:**
  ```bash
  python3 -m pytest tests/
  ```

## 3. Архитектурные особенности и правила кодинга

- **Безопасность и API-ключи (КРИТИЧНО):** Никогда не хардкодьте API-ключи и не сохраняйте их в файлах `.env`. Ключи для внешних сервисов (Tavily, Firecrawl, Exa, Olostep) динамически читаются из in-memory хранилища (vault) по пути `/dev/shm/agent_vault`. См. `searxng_gateway/vault.py`.
- **Stateless:** Сервер не имеет состояния. Не требуется реализовывать механизмы бэкапов.
- **Модификация SearXNG:** Gateway обеспечивает *read-only* доступ к SearXNG (только чтение). Агенты не должны пытаться изменять настройки SearXNG или включать/выключать поисковые движки через этот шлюз.
- **Структура:** Это монорепозиторий. Сервер динамически изменяет `sys.path` для импорта `memory_gateway` из родительской директории (если применимо).
- **Архитектура инструментов:** Возвращаются только сырые данные (без LLM-синтеза). Доступны инструменты `search_web`, `searxng_health`, `deep_research` и `hybrid_search`.

## 4. Советы для будущих ИИ-агентов

- **Изучите `vault.py`:** Понимание того, как работает получение ключей из `/dev/shm/agent_vault`, критически важно при добавлении новых провайдеров или отладке существующих. Не ищите ключи в переменных окружения, кроме базовых настроек вроде `SEARXNG_URL`.
- **Проверяйте наличие зависимостей:** Убедитесь, что перед запуском тестов вы установили проект с флагом `[dev]`, иначе `pytest` может не найти локальные модули.
- **Не меняйте конфигурацию окружения без необходимости:** Если тесты падают, сначала ищите проблему в коде или в моках, а не пытайтесь сразу менять версии пакетов в `requirements.txt` или `pyproject.toml`.
