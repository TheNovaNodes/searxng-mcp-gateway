# Инструкции для ИИ-агентов (AGENTS.md)

Добро пожаловать в репозиторий `searxng-mcp-gateway`! Этот файл содержит ключевую информацию и правила для успешной работы в данном проекте.

## 1. Стек и зависимости
Проект представляет собой MCP (Model Context Protocol) сервер, написанный на **Python**.

**Основные зависимости:**
- **Python >= 3.10**
- `mcp>=1.0.0` — базовый SDK для создания MCP-сервера. Используется `FastMCP`.
- `requests>=2.28.0` — HTTP-клиент для взаимодействия с SearXNG и внешними API.
- **Опционально (для тестов):** `pytest>=7.0.0`, `pytest-cov>=4.0.0`.
- **Интеграция:** ожидается наличие внешнего пакета `memory-gateway` из монорепозитория, путь к которому динамически добавляется в `sys.path`.

## 2. Команды верификации
Перед любым коммитом или сдачей задачи (Pull Request) ты **обязан** запустить следующие команды, чтобы убедиться в отсутствии регрессий и работоспособности кода:

- **Запуск тестов:**
  ```bash
  pytest tests/
  ```
- **Проверка здоровья (Health check):**
  *(Если файл `test_health.py` присутствует)*
  ```bash
  pytest tests/test_health.py
  ```
- **Запуск сервера (для ручного тестирования и проверки инициализации):**
  ```bash
  python -m searxng_gateway.server
  ```
  *(Также доступен алиас `searxng-mcp-gateway` после установки пакета)*

## 3. Архитектурные особенности и правила кодинга

- **Безопасность и API-ключи (In-memory Vault):** Ключи от внешних API (Exa, Firecrawl, Tavily и др.) **не хранятся в коде или в .env-файле**. Вместо этого они считываются из оперативной памяти (`/dev/shm/agent_vault`) с использованием регулярных выражений (см. `vault.py`). Ни в коем случае не хардкодь ключи и не логируй их!
- **Асинхронность и многопоточность:** В гибридном поиске (`hybrid_search` в `server.py`) для распараллеливания запросов к SearXNG и внешним API применяется `concurrent.futures.ThreadPoolExecutor`. Обращай внимание на потокобезопасность при добавлении нового функционала.
- **Отказоустойчивость (Circuit Breakers):** Взаимодействие с внешними API (Echelon) использует балансировщики и circuit breaker-ы (упоминается в `echelon.py` и `server.py`, проверяется в `ecosystem_health`). Любой новый внешний вызов должен использовать аналогичную стратегию graceful fallback (плавной деградации, если API недоступно), не роняя сервер. Обработка исключений в `mcp.tool` методах не должна крашить приложение.
- **Динамический импорт смежных проектов:** В `server.py` реализован хак для динамического добавления родительской директории (монорепозитория) в `sys.path`, чтобы подключить `memory_gateway`. Будь осторожен при рефакторинге путей.

## 4. Советы для будущих ИИ-агентов
- **Не ломай абстракции инструментов:** Инструменты `search_web`, `deep_research` и `hybrid_search` ожидают отдачи "сырого" JSON. Не добавляй LLM-синтез в самом шлюзе (это зона ответственности агентов, использующих шлюз).
- **Читай логи ошибок:** Если тесты падают, посмотри на traceback. Обрати внимание, что некоторые тесты могут требовать mock-ов (заглушек) для `requests` или отсутствующего `/dev/shm/agent_vault`.
- **Никаких мутаций внешнего движка:** Наш MCP шлюз должен быть **read-only** для SearXNG. Не добавляй инструменты для изменения конфигурации SearXNG.
- **Следи за ресурсами (API-квотами):** Гибридный поиск потребляет платные API, поэтому он должен применяться с осторожностью. Вся бизнес-логика падений API должна маршрутизироваться на бесплатные/дешевые fallback'и (например, Firecrawl -> Olostep при обнаружении WAF).
- **Вноси изменения атомарно:** Не переписывай файлы целиком без необходимости. Делай минимально необходимые правки. Обязательно проверяй их тестами!
